# ארכיטקטורת צד לקוח (Frontend Architecture)

מסמך זה מתאר את ארכיטקטורת צד הלקוח והתצוגה (Frontend) של פרויקט **Bingo Online**. ארכיטקטורה זו מיועדת לספק חוויית משתמש (UX) חלקה, זמני טעינה אפסיים, וניצול חכם של רוחב הפס וזיכרון המטמון של הדפדפן.

## 1. תשתית ובנייה (React & Vite)
- **Vite:** פלטפורמת הבנייה (Build Tool) של האתר. בניגוד לכלים מיושנים (כמו Webpack הבסיסי), Vite מספק זמני בנייה מהירים במיוחד ודוחס את קבצי האתר בצורה אופטימלית לסביבת הפרודקשן.
- **Component-Based UI:** האתר בנוי בארכיטקטורת רכיבים (Components) ב-React, מה שמאפשר שימוש חוזר בקוד (למשל, אותו רכיב "עגלת קניות" מופיע גם בדף הבית וגם בתפריט העליון) ותחזוקה קלה של עיצוב המערכת.

## 2. אופטימיזציית טעינה (Load Time & Chunking)
- **טעינה "עצלה" (React Lazy Loading):** במקום לאלץ את הדפדפן להוריד את כל קוד האתר (כולל פאנל הניהול הכבד) כבר במסך הבית, האתר מוגדר לטעון קוד רק לפי דרישה. גולש רגיל יוריד אך ורק את קבצי החנות. קוד הניהול יורד רק אם מנהל מאומת נכנס לדף המתאים. זה חוסך מגה-בייטים של נתונים בכל כניסה.
- **פיצול חבילות (Vite Chunk Splitting):** קובץ ההגדרות של Vite מפצל את ספריות הקוד החיצוניות (כמו React, Lucide Icons) מקוד האתר שלנו לתוך "Vendor Chunk". היתרון העצום: הדפדפן שומר את הספריות האלו בזיכרון מטמון ארוך טווח. כשאנחנו נעדכן קוד באתר, הגולשים יצטרכו להוריד רק את העדכון הקטן שלנו, ולא את כל הספריות החיצוניות מחדש.

## 3. אופטימיזציית נכסים ועיצוב (Asset Optimization)
- **תמונות WebP:** כל תמונות הרקע הכבדות והטקסטורות של הבדים הומרו מפורמט PNG/JPG לפורמט `WebP` מודרני. פעולה זו מקטינה את משקל התמונות ב-80% בממוצע מבלי לפגוע באיכות הוויזואלית, מה שמאפשר גלישה מיידית וחלקה (בעיקר למשתמשי מובייל על רשת סלולרית).
- **CSS מודולרי ואפקטים:** עיצוב האתר נעשה ב-Vanilla CSS עם משתני צבע (Variables) לניהול מצבי "יום" ו"לילה" (Dark Mode / Light Mode). הכל נטען במהירות ללא ספריות עיצוב כבדות ומיותרות שמאיטות את רינדור הדף.

## 4. שרת הפרונט-אנד (Nginx Reverse Proxy)
בסביבת הייצור, קבצי ה-React אינם רצים על "שרת" אמיתי, אלא מוגשים כקבצים סטטיים על ידי שרת **Nginx** עוצמתי.
- **דחיסת Gzip:** ה-Nginx מוגדר לדחוס (Zip) את קבצי ה-JS וה-CSS לפני שהוא שולח אותם לדפדפן של הלקוח. הפעולה הזו מכווצת את גודל האתר ב-70% וגורמת לממשק לעלות בשבריר שנייה.
- **ניתוב חכם (Reverse Proxy):** ה-Nginx מתפקד כ"שוטר תנועה". כשמשתמש מבקש דף, Nginx מגיש לו את React. כשמשתמש מנסה להתחבר או לפנות ל-API, ה-Nginx מעביר את הבקשה בשקט לשרת ה-FastAPI (ה-Backend) מבלי לחשוף את הפורט האמיתי שלו לרשת.
- **כותרות אבטחה (Security Headers):** דרך Nginx אנו אוכפים את מדיניות ה-CSP (Content Security Policy) ומונעים מתקפות של Clickjacking ו-XSS על ידי חסימת ניסיונות להטמיע את החנות שלנו בתוך Iframe של אתרי הונאה.

## 5. ניטור ובקרת שגיאות (Error Monitoring)
- **Sentry Error Tracking:** האתר משלב בתוכו חיישן של מערכת Sentry. אם גולש מנסה לבצע פעולה שגורמת לקריסה בצד הלקוח (לדוגמה, באג ב-React שגורם למסך לבן), המערכת תופסת את הקריסה מאחורי הקלעים ומשדרת דוח מפורט למפתחים. הדוח כולל את שורת הקוד המדויקת שגרמה לבעיה, גרסת הדפדפן של המשתמש, וסדרת הפעולות שהובילה לקריסה.

---
> **סיכום:** צד הלקוח (Frontend) של הפרויקט בנוי כדי לספק ביצועי קצה (Edge Performance). השילוב של טעינה עצלה, פיצול חבילות קוד, תמונות WebP קלילות, ושרת Nginx שדוחס את המידע, מבטיח שהאתר "יעוף" גם על מכשירי טלפון ישנים או אינטרנט איטי.
