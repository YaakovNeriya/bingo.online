# תהליכי עבודה נכונים (CI/CD ו-DevOps)

מסמך זה מתאר את תהליך ה-Continuous Integration & Continuous Deployment (CI/CD) של פרויקט **Bingo Online**. התהליך נבנה כדי להבטיח איכות קוד, אבטחת מידע קפדנית, ופריסה (Deployment) חלקה לחלוטין ללא מגע אדם בשרת הייצור (Oracle Cloud).

## 1. דחיפת קוד (Push) והתחלת התהליך
כל עדכון קוד שנדחף (Push) לענף הראשי (`main` או `master`) ב-GitHub מתחיל באופן אוטומטי את שרשרת הפעולות (Workflow) שמוגדרת בקובץ `.github/workflows/deploy.yml`.

## 2. סריקת אבטחה (Dependency Scanning)
לפני שבונים את האתר, המערכת מוודאת שלא הכנסנו בטעות ספריות עם פריצות אבטחה (CVE) מוכרות:
- **בצד שרת (Backend):** מורצת פקודת `pip-audit` שסורקת את קובץ ה-`requirements.txt`.
- **בצד לקוח (Frontend):** מורצת פקודת `npm audit` שסורקת את ספריות ה-React.
> **הערה:** אם מתגלה ספרייה מסוכנת, התהליך כולו נעצר מיד, השרת נשאר מוגן, ונשלחת התראה למייל.

## 3. בניית תמונות דוקר (Build Stage)
לאחר אישור האבטחה, GitHub Actions מריץ בנייה של תמונות Docker (Images):
- **אופטימיזציה:** אנחנו משתמשים ב-`Multi-stage builds`. זה אומר שסביבת הפיתוח (לדוגמה קבצי ה-Node.js הכבדים של ה-Frontend) נמחקת, ורק הקבצים המוכנים לריצה (Compiled) נדחסים לתמונה הסופית.
- **משקל זעיר:** ה-Backend משתמש בגרסאות `slim` רזות כדי למנוע עומס על שרת ה-Oracle שלנו.

## 4. דחיפה למאגר העולמי (Push to Docker Hub)
תמונות הדוקר המוכנות (Frontend ו-Backend) מקבלות תגית (Tag) ונשלחות למאגר העולמי ב-Docker Hub. הפעולה הזו מתבצעת בעזרת הרשאות חסויות (`DOCKERHUB_USERNAME` ו-`DOCKERHUB_TOKEN`) השמורות בצורה מוצפנת ב-GitHub Secrets.

## 5. פריסה אוטומטית מלאה (Automated SSH Deployment)
זהו השלב המתקדם ביותר. אין צורך להתחבר יותר ידנית לשרת.
גיטהאב משתמש בכלי מאובטח בשם `appleboy/ssh-action` כדי לפתוח חיבור מוצפן לשרת ה-Oracle. בזמן החיבור, גיטהאב מבצע את הפעולות הבאות:
1. **הזרקת סודות (Secret Injection):** גיטהאב מייצר קובץ `.env` ישירות על השרת מתוך ה-GitHub Secrets. כך סיסמאות מסד הנתונים (`DB_PASSWORD`) ומפתחות ההצפנה (`SECRET_KEY`) לעולם לא נשמרים בתוך הקוד עצמו.
2. **משיכת קוד עדכני:** הרצת הפקודה `docker-compose pull` כדי לשאוב את התמונות החדשות מ-Docker Hub.
3. **שדרוג מסד נתונים (Automated Migrations):** הרצת סקריפט אוטומטי (`alembic upgrade head`) שמוודא שמבנה מסד הנתונים מתעדכן בצורה בטוחה בהתאם לקוד החדש (למשל, הוספת עמודות חדשות) מבלי למחוק מידע קיים.
4. **הפעלה מחדש (Restart):** הרצת הפקודה `docker-compose up -d`. השרת עולה מחדש בצורה שקטה, עם מגבלות הזיכרון החדשות שהגדרנו (Docker Limits) כדי למנוע קריסות (Memory Leaks).

## 6. מערכות חיות (Post-Deployment Health)
מרגע שהמערכת באוויר, מספר מנגנוני ביטחון נכנסים לפעולה:
- **Health Checks:** דוקר בודק כל הזמן את דופק המערכת. שרת שנתקע יקבל "החייאה" ויופעל מחדש אוטומטית.
- **Log Rotation:** קבצי הלוג נשמרים בצורה מעגלית (מוגבלים ל-10MB) כדי למנוע סתימה של הדיסק הקשיח.
- **Gunicorn:** מערכת ניהול תהליכים מפקחת על הפעילות הפנימית של פייתון לביצועים אולטימטיביים.
- **Nginx & Security Headers:** כל התעבורה עוברת סינון והצפנה נגד מתקפות XSS, ניחוש סיסמאות מסיבי (Rate Limiting) ועוד.

---
> **סיכום:** ארכיטקטורת ה-CI/CD הזו (GitOps) מבטיחה שכמפתחים - אנחנו נוגעים רק בקוד ועושים `push`. כל שאר התהליך (בדיקות אבטחה, בנייה, עדכון שרת, אבטחת סיסמאות והשגחה) קורה באוטומציה מוחלטת מאחורי הקלעים.
