# 🛡️ תיעוד מערך הגיבויים (Bingo Online)

מסמך זה מתאר את ארכיטקטורת מערך הגיבויים של בסיס הנתונים (MySQL), כיצד הוא פועל מאחורי הקלעים, ואת דרכי השחזור במקרה חירום.

---

## 1. סקירת המערכת
מערך הגיבויים פועל כשירות עצמאי לחלוטין (Container ב-Docker) הרץ במקביל לאתר ולבסיס הנתונים. מטרתו היא לדגום את מסד הנתונים פעם ביום, לוודא שהמידע תקין, ולשמור עותקים מאובטחים גם מקומית בשרת וגם בענן (Google Drive).

### תכונות מרכזיות:
- **אוטומציה מלאה:** תזמון קבוע בכל לילה בשעה `03:00` לפנות בוקר.
- **בדיקות תקינות (Validation):** הקובץ עובר שתי רמות בדיקה כדי להבטיח שאינו פגום טרם העלאתו.
- **גיבוי היברידי:** שמירת הקובץ האחרון בשרת לגישה מהירה, ושמירת 30 הימים האחרונים בענן.
- **ניהול נפח (Retention):** מחיקה אוטומטית של קבצים ישנים מגוגל דרייב, למניעת חריגה משטח האחסון.

---

## 2. איך זה עובד מאחורי הקלעים? (Workflow)

כאשר השעון מורה על השעה 03:00, סקריפט מיוחד (`backend/run_backup_scheduler.py`) מפעיל את תהליך הגיבוי (`backend/backup_to_drive.py`). התהליך מורכב מ-5 שלבים:

### שלב א': חילוץ הנתונים (Dump & Compress)
הסקריפט מפעיל פקודת `mysqldump` המתחברת למסד הנתונים (MariaDB/MySQL) ושואבת את כל הטבלאות. כדי לחסוך מקום וזמן, הנתונים נדחסים בזמן אמת בעזרת `gzip` ונוצר קובץ בסיומת `.sql.gz`.

### שלב ב': בדיקות תקינות כפולות 🔍
כדי למנוע מצב של העלאת קובץ פגום עקב שגיאת רשת או קריסת המסד, מתבצעות שתי בדיקות:
1. **Gzip Integrity:** המערכת בודקת שהקובץ המכווץ אינו מושחת וניתן לפתיחה.
2. **SQL Signature:** המערכת פותחת מציצה אל השורות האחרונות בקובץ ומוודאת שמופיע שם הכיתוב `Dump completed`. הימצאות כיתוב זה מבטיחה שכל הנתונים נמשכו במלואם ללא קטיעות.

### שלב ג': העלאה לגוגל דרייב ☁️
באמצעות הרשאות ה-OAuth 2.0 (קובץ ה-`token.json`), הסקריפט ניגש ל-Google Drive.
הוא מחפש תיקייה בשם **"Bingo Backups"** (ואם אינה קיימת - יוצר אותה), ומעלה אליה את קובץ הגיבוי תחת שם הכולל את חותמת התאריך והשעה (לדוגמה: `backup_2026-06-29_03-00-00.sql.gz`).

### שלב ד': מחיקת גיבויים ישנים בענן (Retention)
לאחר ההעלאה, הסקריפט שולח שאילתה לדרייב לחיפוש כל הקבצים בתיקייה שגילם עולה על **30 ימים**. אם קיימים כאלו, הוא שולח פקודת מחיקה לצמיתות כדי לפנות מקום.

### שלב ה': עדכון הגיבוי המקומי בשרת 💾
בסיום כל התהליך בהצלחה, הקובץ החדש מועבר לתיקיית הגיבויים בשרת (`/backups`) תחת השם הקבוע `latest_backup.sql.gz`. פעולה זו דורסת את קובץ האתמול ומוודאת שתמיד יש לנו בשרת בדיוק קובץ אחד מעודכן, מה שמונע בזבוז שטח דיסק בשרת.

## 3. קבצי המערכת

| קובץ / נתיב | תפקיד |
| :--- | :--- |
| `docker-compose.prod.yml` | מכיל את הגדרת שירות הגיבוי (`db_backup`) והחיבור שלו לרשת הפנימית ולמסד. |
| `backend/Dockerfile.prod` | עודכן כדי לכלול את חבילת `default-mysql-client` ההכרחית לשליפת הנתונים. |
| `backend/backup_to_drive.py` | הלב של המערכת. אחראי על הדגימה, הבדיקה וההעלאה לדרייב. |
| `backend/run_backup_scheduler.py` | שעון העצר שרץ ברקע 24/7 ומפעיל את הגיבוי בשעה היעודה. |
| `credentials.json` | תעודת הזהות של האפליקציה שלנו מול שרתי Google API. |
| `token.json` | "מפתח המאסטר" המאפשר לסקריפט לכתוב לדרייב מבלי לבקש הרשאה בכל פעם מחדש. |
| `restore.sh` | סקריפט עזר פשוט להרצה במקרה של שחזור נתונים. |

---

## 4. תהליך שחזור נתונים (Restore) 🚑

במידה והשרת קרס לחלוטין ויש צורך לאחזר את הנתונים, הפעולה פשוטה ומהירה:

> [!CAUTION]
> שחזור נתונים **ידרוס** את כל הנתונים הקיימים כרגע במסד! ודא שאתה באמת רוצה לשחזר.

1. **הורדת הגיבוי:** 
   היכנס לגוגל דרייב לתיקיית `Bingo Backups` והורד את הקובץ של התאריך הרצוי למחשב (הוא יהיה בסיומת `.sql.gz`).
2. **העברה לשרת:** 
   העבר את הקובץ אל התיקייה הראשית של הפרויקט בשרת (איפה שנמצא הקובץ `docker-compose.prod.yml`).
3. **הפעלת השחזור:**
   הרץ מהטרמינל את הסקריפט עם שם הקובץ:
   ```bash
   ./restore.sh backup_2026-06-29_03-00-00.sql.gz
   ```
   *הערה: הסקריפט יישאב את הקובץ ישירות אל תוך ה-Docker של MySQL.*
4. המתן מספר שניות להודעת `Restore completed successfully!`.

## 5. תקלות נפוצות

> [!WARNING]
> פג תוקף של Token התחברות לגוגל
> 
> **סימפטום:** הגיבויים הפסיקו לעלות לדרייב (ניתן לראות בלוגים הודעות שגיאה של Authentication).
> **סיבה:** גוגל ביטלו את הגישה (למשל אם שינית סיסמה לחשבון).
> **פתרון:** מחיקת הקובץ `token.json` הישן, והרצה מחדש של הפקודה:
> `docker exec -it fabric_backup python auth_google.py`
> ואז אישור הגישה מחדש דרך הדפדפן.
