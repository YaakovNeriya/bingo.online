# תכנון מנגנון שיתוף חכם (Dynamic Open Graph)

הבקשה שלך מצוינת ונוגעת בנקודה טכנולוגית מעניינת מאוד: כשהאתר בנוי כ-SPA (עם React), כל התוכן נטען בצד הלקוח (JavaScript). אבל בוטים של וואטסאפ, פייסבוק ואינסטגרם **לא מריצים JavaScript**. הם קוראים רק את ה-HTML הגולמי הראשוני. 
לכן, אם לא נטפל בזה, כל קישור למוצר ספציפי יציג את הלוגו והתיאור הכללי של "בינגו בדים" במקום את התמונה של הבד עצמו.

להלן אפשרויות לפתרון הארכיטקטורה ורעיונות לפיתוח עתידי של מנגנון השיתוף, לאישורך.

## 1. איך נפתור את הזרקת ה-OG Tags? (ארכיטקטורה)

### הארכיטקטורה הנבחרת (The Sweet Spot): NGINX + FastAPI + Redis
לאחר דיון מעמיק, זוהי הארכיטקטורה המדויקת שניישם כדי לקבל מקסימום ביצועים בלי לשכתב את האתר ל-Next.js:

1. **זיהוי בתשתית (NGINX):** 
   נגדיר ב-NGINX חוק חכם: אם הבקשה מגיעה מבוט (לפי ה-User-Agent כמו `WhatsApp` או `facebookexternalhit`), העבר אותה ל-FastAPI לנתיב מיוחד (למשל `/api/v1/share/product/{id}`). אם זה אדם - העבר אותו ל-React (Vite) כרגיל.

2. **זיכרון מטמון מהיר (Redis Caching):**
   במקום ש-FastAPI יפנה למסד הנתונים בכל פעם שפייסבוק סורק את הלינק, נשמור את תוצאת ה-HTML ב-Redis. 
   - **היתרון:** מהירות של חלקיקי שנייה.
   - **שליטה:** כשמנהל האתר מעדכן מחיר או תמונה של בד, ה-Backend פשוט ימחק את המטמון של אותו מוצר מ-Redis באופן נקודתי. הבוט הבא יקבל את המידע המעודכן מיד.

3. **ניטור והתראות (Observability):**
   מאחר ומדובר במנגנון שיווקי קריטי אך שקט (לקוחות לא מתלוננים אם הקישור בוואטסאפ לא מראה תמונה), ניצור מנגנון לוגים נפרד (`og_monitor`). כל שגיאה ביצירת ה-OG Tags תקפיץ שגיאה בולטת בלוגים (ואפשר בעתיד לחבר להתראות למייל/וואטסאפ של המנהל).



## 2. מה עוד אפשר לעשות כשמשתפים בד? (רעיונות לפיתוח עתידי)

> [!TIP]
> **הנה כמה רעיונות שהופכים סתם "שיתוף לינק" למנגנון שיווקי מתקדם:**

1. **תמונה עם חותמת (Dynamic Watermarking):** 
   במקום שוואטסאפ ישאב את התמונה הרגילה של הבד, ה-FastAPI יכול לייצר (On-the-fly באמצעות ספריה כמו Pillow) תמונה חדשה שמשלבת את תמונת הבד + מסגרת יפה עם הלוגו של "בינגו בדים" + פס אדום שאומר "הלהיט של העונה!" או "אזל המלאי" + המחיר. ככה ההודעה בוואטסאפ נראית כמו פרסומת מקצועית!

2. **קישורי "הוספה מהירה לעגלה" (Deep Linking):**
   אפשר לייצר כפתור "שתף בוואטסאפ לחברה" ששולח קישור עם פרמטר מיוחד (למשל `?action=add_to_cart`). ברגע שהחברה לוחצת על הקישור, המערכת לא רק פותחת לה את המוצר, אלא מיד מקפיצה פופ-אפ: "חברה שלך המליצה לך על הבד הזה! רוצה להוסיף אותו לעגלה?".

3. **מעקב וסטטיסטיקות שיתופים (Analytics):**
   ברגע שמייצרים את הלינק לשיתוף, מוסיפים לו פרמטר חבוי. ככה בפאנל הניהול של בינגו, נוכל לראות:
   - "הבד הזה שותף 150 פעמים השבוע" (אינדיקציה מעולה למגמות אופנה לפני שקונים סחורה מהספק).
   - "כמה אנשים נכנסו לאתר דרך קישורים ששותפו".

4. **תוכנית שותפות (Referrals):**
   כל לקוחה (שיש לה חשבון) שתשתף את הקישור, הקישור יכיל את ה-ID שלה. אם הלקוחה החדשה נכנסת וקונה, המשתפת מקבלת הנחה/נקודות בעגלה הבאה שלה.

## 3. נקודות אחרונות לחידוד טכני (לפני שכותבים קוד)

יש עוד 2 נקודות טכניות קטנות שצריך לסגור כדי שהכל יהיה מושלם:

1. **איך בודקים את זה בסביבת הפיתוח?**
   כרגע אנחנו מריצים את ה-Frontend עם Vite (`npm run dev`) ולא עם שרת פרוקסי מלא כמו NGINX שרץ ב-Production. כדי לפתח ולבדוק את זה, נצטרך לפנות ישירות לכתובת ה-API מהדפדפן שלנו (למשל `http://localhost:8000/api/v1/share/product/123`) כדי לראות את התגיות בעיניים, לפני שאנחנו מטמיעים את החוקים בשרת האמיתי למעלה.

2. **תמונות מרוכבות (Pillow) ועברית:**
   אם נחליט ללכת על רעיון השיווק של "תמונה עם חותמת" (למשל, הדבקת המחיר והלוגו על התמונה של הבד לפני שוואטסאפ שואב אותה), השרת יצטרך לצייר טקסט על התמונה. **ציור טקסט בעברית על תמונה בפייתון** (RTL) זה משהו שדורש קצת עבודה - נצטרך לטעון קובץ פונט (TTF) שתומך בעברית, ולהשתמש בספרייה שהופכת את כיוון האותיות כדי ש"בד קטיפה" לא ייכתב "הפיטק דב".
